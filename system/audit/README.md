# Audit tool (rev10)

The final interface and the rationale for every view, mode and control: `INTERFACE.md`.

Panels are lettered for reference: A main view (configuration map / contrast overview / VLM statements), B subject × configuration matrix, C image axis, D evidence (trajectories, distributions, appearance map, rewrites), E contrast scatters. Palette: A blue, B orange, one violet accent for selections; families in low-saturation slate, sage and rose; one soft diverging scale for pole locations; verdicts in sage (confirmed), red (contradicted), violet (narrowed, did not move), amber (no shift), grey (other).

One screen, adapting to the window (tested at 1280×760, 1440×900 and 1920×1080): a **main view** (the configuration map, top left, largest) and linked **auxiliary views**: the subject × configuration matrix (top middle), the five contrast scatters stacked on the right, the distributions of one subject (bottom middle) and the image strips (bottom left). The aspect buttons in the header switch every view.

Visual audit of appearance defaults for the model study (`docs/RESEARCH_PROPOSAL.md` §6). It replaces the rev4.1 comparison system in `system/` (kept as design history) for the three audit tasks:
- **T1, displacement vs concentration:** for a contrast A → B, does each subject's output distribution move, tighten or widen?
- **T2, pooled vs per subject:** does the median over subjects hold for every subject?
- **T3, trace to images:** every reading leads back to the images, and the tool shows when a contrast changes more than one declared setting.

## Build and run
On the GPU server, after `source ops/env.sh`:
```bash
python system/audit/build.py
```
It writes `$T2IC_DATA/audit_tool/` (page, `data.js`, 192 px thumbnails). Serve that folder with any static server:
```bash
cd $T2IC_DATA/audit_tool && python -m http.server 8772 --bind 127.0.0.1
```
To use it from another computer, open an SSH tunnel and browse to http://127.0.0.1:8772/:
```bash
ssh -N -L 8772:127.0.0.1:8772 h200
```
Rebuild whenever more groups have been generated and CLIP-scored. The pages load `data.js?v=<build time>`, so a browser never shows a cached older build. Declared settings include the scheduler read from each model folder. Rewritten-prompt groups of the LLM study (`$T2IC_DATA/llm_study/<group>__<rewrite>/`) are added automatically as extra configurations (dotted arrows); they never enter the frozen scale or the map's common centre. The scale is marked provisional (amber dot, top right) until all 12 open configurations are included.

## Views
| View | Encoding | Interaction |
|---|---|---|
| **Main view: configuration map** and auxiliary **matrix** | **Configuration map** for the chosen aspect: each configuration is a point (colour = family) at its typical location (x, median over subjects of the distance from the subjects' cross-configuration median, in scale units) and spread (y, median IQR in scale units). Arrows are the designed contrasts: solid = guidance only, dashed = package (several settings change). The axes cover every configuration and 80% of the per-subject positions; per-subject positions beyond that are drawn at the edge as triangles. **Subject × configuration matrix**: colour = location of that configuration for that subject (diverging between the two poles); a row whose colour flips is a subject-dependent default | aspect buttons; hover a configuration to see its subjects in the map and its matrix column; hover a matrix row (or cell) to see where every configuration puts that subject, linked to each configuration's typical position; click a point, cell or arrow to set the A → B pair for the levels below |
| **Contrast overview** (main view, second mode ▦) | every designed contrast (rows) × retained aspect (columns); per glyph an arrow from the centre for the pooled displacement (length = Δ, colour = direction, dashed while the 90% interval reaches inside the margin) and a filled circle against a dashed reference circle for the spread ratio (solid outline once the interval lies beyond the margin); ⇄ n = subjects displaced against the pooled direction (shown from 3) | toggle ◎/▦ in the main view header; hover a glyph for the estimates; click to make that pair and aspect current |
| **Appearance map** (bottom-middle panel, third mode ⁘) | all images of the chosen subject from every configuration placed by a shared t-SNE of their CLIP image embeddings (computed by `build.py`); other configurations as faint dots in family colour; A and B as coloured dots; no density contours (rev8: t-SNE keeps only local neighbourhoods, so areas and distances are not read as spread; it is an index to images) | hover a dot to see the image; A/B dots highlight the image in the strips |
| **Reversal detection** (matrix) | a Δ column shows the selected pair's shift per subject (bars from the centre, dashed lines at ±0.5); subjects displaced against the pooled direction beyond the margin are flagged in amber in the matrix and in the contrast scatters; the ⇄ n badge counts them | click the badge to step through the flagged subjects; ⇅ orders rows by the shift instead of by category |
| **Statement view** (main view, third mode ❝) | a glyph matrix (rows: pooled and the 24 subjects; columns: the five aspects, variety, other); one glyph per free-text statement (circle Qwen-4B, square Mistral-24B) coloured by the audit verdict; text only on hover and for the selected statement. Every free-text statement two VLMs made about the selected pair (`experiments/llm_study/`, Q5), coded to an aspect and direction, with the audit's verdict for the same contrast, level and subject: confirmed (green), narrowed but did not move (violet), audit finds no shift (amber), contradicted (red), outside the measured aspects or undecided (grey); a bar summarises the verdicts | VLM and level filters; click a statement to select its aspect and subject so every other view shows the evidence; pairs without statements list the described pairs |
| **Validation marks** (rev6) | an aspect that people have not validated on the configurations of the selected pair (`META.validity`, annotation rounds 1–3) is faded in its contrast scatter and the overview, struck through in the aspect buttons and marked ⊘ (tooltip names the annotation round) | — |
| **Rewrite view** (bottom-middle panel, fourth mode ✎) | for a pair whose one side uses LLM-rewritten prompts (dotted arrows on the map): each rewritten image at x = what its rewrite says about the aspect (CLIP text score of the rewrite minus that of the original prompt, text units) and y = where the image lands (scale units from the original prompt's median); the original prompt's images as the tick column at x = 0; the margin band | hover a dot for the rewrite (word families highlighted) and its image |
| rev7: **focus + context main view** | the configuration map fits its axes to the data; the selected A and B show where they put each of the 24 subjects (faint dots and density contours at common levels, so a spread-out configuration shows a wide faint region and a concentrated one a small dense region); only A, B and the hovered configuration are labelled, other configurations are small dots; the A → B arrow is emphasized (drawn even when the pair is not a designed contrast) | drag one configuration onto another to compare |
| rev7: **verdict glyphs on the aspect buttons** | each aspect button shows the selected pair's pooled verdict: an arrow for the shift (solid = displaced, dashed = unresolved, a bar = same place) and a disc against a dashed ring for the spread (smaller = narrower; filled once resolved); struck through when the aspect is not validated for the pair | hover for the estimates; click to switch aspect |
| rev7: **findings board** (☆ in the header) | saved views as cards: pair, aspect, subject, modes, selected seeds and brushed subjects, with a verdict and a note | + saves the current view; click a card to return to it; ⤓ exports CSV (kept in the browser) |
| Interactions added in rev6 | **subject brushing**: drag a box over empty space in any contrast scatter; the brushed subjects stay bright in all five scatters, are underlined in the matrix, and a hollow violet diamond marks their median (tooltip: brushed vs the others). **Draggable margins**: the small handles on the band edges change the location and spread margins for exploration; verdicts, reversal flags and the contrast overview update, and "margins … ↺" in the header restores the pre-registered values. **Drag to compare**: drag from one configuration on the map onto another to make them A → B. **Statement view**: click a verdict in the bar to filter; ✓ / ✗ record the analyst's own verdict (kept in the browser, ⤓ exports CSV; used for task T4 in the expert study). **Rewrite view**: word-family chips highlight rewrites that mention lighting, time of day, etc.; brushing rewrites selects their seeds everywhere | |
| Header | A and B selectors with their colours (blue, orange); chips for every declared setting that differs; ⚠ n when more than one differs (not attributable to one setting) | swap A and B |
| Auxiliary: five contrast scatters (right column) | one dot per subject: x = location shift Δ = (median_B − median_A) / s_aspect, y = log IQR ratio (spread); shaded bands = frozen practical margins (\|Δ\| < 0.5, ratio within 1/1.5–1.5); diamond = median over subjects with a hierarchical bootstrap 90% interval | hover a dot to highlight the same subject in all five plots and preview it below, click to pin; hover the diamond for the pooled estimate and how many subjects moved each way |
| Auxiliary: **paired-seed trajectories** (default mode of the bottom-middle panel, ⫽) | for the chosen subject and aspect, every image of A joined to the image of B made from the same seed by a smooth curve; solid when A and B share pipeline and resolution (same starting noise), dashed and rank-matched otherwise (rev8: the panel states which, since rank-matched curves are a quantile alignment, not trajectories); the thick curve joins the medians; IQR bands on both rows. Curves leaning one way = displacement, converging = concentration | hover a curve to highlight both images in the strips |
| Auxiliary: distributions of one subject (∿) | smooth kernel density curves of A and B per aspect on a common axis (scale units, 0 = A's median); rug ticks are the individual images | click a row to choose the aspect; hover a tick to highlight the image |
| Auxiliary: **image axis** (rev6, replaces the sorted image grid) | every image of A (above) and B (below) placed at its score on the chosen aspect (scale units from A's median), three rows per side, overlapping where images crowd; band = location margin; triangles = medians | **brush the thin track** above or below the axis to select images: the same seeds are selected on the other side, in the trajectories, the appearance map, the rugs and the rewrite view ("where did these images go?"); click an image to select its seed; **▶** moves every image of A to where its same-seed image lands in B and back (displacement = the pile travels, concentration = it gathers) |

The page is written with D3 v7 (selections, data joins, scales, axes, areas, transitions); `build.py` (Python) only prepares the data. Numbers appear only in tooltips, except in figure mode (rev8, below). Intervals are 90% bootstrap intervals with 400 resamples, paired by seed when A and B share the same weights. The display labels ("displaced", "same place") follow the frozen margins; the primary analysis is done separately in a script, not in the tool.

## rev8 (2026-10-22): changes after the external review (`docs/REVIEW_2026-10-22.md`)
- **Figure mode** for screenshots in the paper (since rev10 opened with `index.html?figure`, not a button); the interactive view stays as before. It adds numeric axes to the configuration map with their meaning (x: typical location in scale units from each subject's cross-configuration centre; y: typical spread, median IQR), the number of the selected pair's subjects beyond the axes, the margin values on the band edges of the contrast scatters, the pooled shift and spread ratio in each scatter's title, and, on the selected arrow, how many declared settings change ("not attributable to one" when more than one).
- **Intervals from the scripted analyses.** `build.py` embeds the pooled 90% intervals of `results/q1`, `results/q3` and `results/q4` (10,000 resamples) as `META.official`; for those designed contrasts the tool shows them instead of its own 400-resample intervals (★ in figure mode; the tooltip names the source). Point estimates and per-subject intervals are still computed in the browser.
- **No silent clamping on the map:** a subject of the selected pair beyond the fitted axes is drawn at the edge as a triangle pointing outward.
- **Trajectories** state whether curves follow one image (same starting noise) or are a rank match (quantile alignment).
- **Appearance map** without density contours.
- Tested on a synthetic build with the same data layout (12 configurations × 24 subjects × 32 seeds); not yet rebuilt on the server.

## rev9 (2026-10-22): audit trail (main view, fourth mode ⛓)
The external review asked for one interface that takes each kind of language claim to the images (`docs/REVIEW_2026-10-22.md`). The audit trail is that route, as a fixed chain of four stages, the same for all three roles of language:

| Stage | Shows | Link to the next stage (audit verdict) |
|---|---|---|
| 1 Claim | the source (● Qwen-4B, ■ Mistral-24B statement; ✎ rewritten prompt; ≡ axis defined in words), the claim in one line, and the claimed direction on the aspect (or the claimed change in variety) | ✓ supported, ✗ contradicted, ≈ narrowed but did not move, ○ did not move, ⊘ not validated, – the claim says nothing on this aspect. For a statement: the Q5 verdict. For a rewrite: the sign of what the rewrite says (text side) against where its image lands (image side, beyond the margin). For an axis: whether people validated it for this pair |
| 2 Measurement | the per-subject contrast scatter of the aspect with the margins, the selected subject and the pooled estimate | for a pooled claim, whether the pooled shift is beyond the margin; for a subject, ✓ same direction as the pool, ✗ reversed, ⇄ moved although the pool did not (pooling hides it), ≈ narrowed only |
| 3 Subject | A and B of that subject on the aspect (dots, medians, margin band), the chosen seed ringed | the analyst's own verdict after looking at the images (✓ / ✗) |
| 4 Images | A and B from the same seed (or matched by rank when pipeline or resolution differ), stepping through seeds | — |

- The trail follows the current selection: a selected VLM statement (❝, and the ⛓ button in its detail), otherwise the rewritten prompt of the shown seed when the pair has a rewritten side (dotted arrow), otherwise the aspect's axis.
- The analyst's verdict belongs to one chain (claim, pair, subject, seed) and is cleared when any of them changes.
- **+ save trail** stores the chain with its view in the browser; a saved row shows its three link verdicts and restores the view, the statement and the verdict on click; ⤓ exports the saved trails as CSV (for the paper's end-to-end cases).
- Tested on a synthetic build with VLM statements and a rewritten-prompt configuration (all three claim kinds, saving, restoring, verdict reset, the other three main modes); not yet rebuilt on the server.

## rev10 (2026-10-22): final interface
See `INTERFACE.md`. Cool, crisp palette (A blue, B orange as the only data hues; families as shapes; teal–ochre pole scale; status colours always with a symbol or shape); figure mode moved to the URL; verdict glyphs removed from the aspect buttons (duplicated the contrast scatters); the findings board removed (the audit trail's saved list is the one record of findings). Tested on a synthetic build with pilot images as thumbnails.

## 1. 迭代过程（2026-10-02）
| 版本 | 做法 | 结果与原因 |
|---|---|---|
| 原型 2 | 以 ViBEx 为参照：每组平均图 + 方面 × 组的迷你箱线图 + 不重叠的缩略图条带 + 双方面散点；只用**并置**比较 3 个模型（截图 `prototype2_coffee_tone.jpg`） | 组一多就不利于探索，各视图的协同交互弱。改为原型 3 |
| 原型 3 rev1–rev2 | 按 Gleicher 的分类：组多时总览用**叠加**（共享投影）和**显式编码**（方面 × 组矩阵），并置只留给挑出的少数几组；选择是所有视图共享的对象；条带显示所有组并加**共用轴刷选**（截图 `dashboard_rev2_common_brush.jpg`） | 保留下来的骨架 |
| 原型 4 | 照搬 PrompTHis 的"设置改动图" | **否决**：PrompTHis 的边编码"prompt 改了什么"，对互相独立的模型样本没有自然含义；只借思路，不借结构 |
| rev3 | 投影图为主视图：缩略图作标记并去重叠，重点组画平滑气泡，自动簇注释框（截图 `rev3_overview.jpg`） | 平铺全部图像太繁杂，看不出总体规律 |
| rev3.1 | 簇卡片总览：每簇一张卡片（来源比例条、3 张代表图、偏向的方面），点开看全部图（截图 `rev3_cluster_cards.jpg`、`rev3_cluster_expanded.jpg`） | **否决**：卡片死板，不是可视化的设计 |
| rev4 | 清爽版：图像空间只有点和**最高密度区域等高线**；视图里不放文字，细节悬停时出现；每个视图只表达一件事（截图 `rev4_overview.jpg`、`rev4_hover_contour.jpg`、`rev4_brush_klein.jpg`） | 外部评审：等高线不能读成集中程度；隐藏组会改变统计基线；条带里的图叠在一起；选择状态不一致 |
| **rev4.1（当前）** | 按评审改进计划第 1–4 项纠错，布局不变（截图 `results/system/`） | 见 `system/README.md` |

## 2. 可写进论文的设计经验
1. **投影图上的包络不能读成集中程度或相似程度。** t-SNE 只保留局部邻近关系，横纵分别归一化和屏幕缩放都会改变形状；每组 8–16 个点时，边界的平滑程度远超样本能支持的精度。投影图只作"发现意外外观的图像索引"，集中程度只在看图核实过的方面分布里比较。
2. **隐藏数据不应改变统计基线。** 例："城市街道 / Turbo / 色调"的集中程度在全部可见时是 0.782，只看三个模型时 0.348，只看 Turbo 时 1.000（rev4）。rev4.1 把分析范围固定为本 prompt 下全部组，隐藏只是不画。
3. **合并 prompt 会藏起反转。** Turbo 构图：房子 +1.31、厨房 −1.33，合并后 +0.07。rev4.1 去掉了"全部 prompt"合并视图。
4. **比较必须带上生成设置。** 原先说的"蒸馏"实际同时改了权重、步数 28→4、CFG 4→1；系统在改动超过一项时提示"不能归因于其中某一项"。重复使用的样本（咖啡上 8 张）不能当独立证据。
5. **"视图之间不重复"要有限度。** 协同视图需要在各视图重复组颜色、参照组和选择提示才能连贯；图例、样本量、参照组、选择范围要常驻（用极小的编码图例，不写说明句），只有具体读数放进悬停。
6. **显示位置与选中判断必须一致。** rev4 中有张图显示时被压进第一格，刷选时却按真实分数判断而漏掉；rev4.1 让每张图的中心放在真实分数处，刷选按图中心判断。
7. **自动测量要能回到图像核实。** 同一批 Turbo 图同时被判为"更像绘画"和"更写实"；方面名称会说过头（"画质"测的是措辞，不是生成质量）。

## 3. 评审建议、尚未采纳的方向（留作讨论或后续）
- 主视图从投影图换成"以图像为依据的对齐方面分布比较"（评审第 5 项）。
- 两个方面的联合查看，用于研究反复出现的组合（色调总配某种构图）。
- 扩展到 20–50 组：可滚动的总览、家族可展开、参照组固定。
- 让 VLM 说出一批图的共同点并变成新方面，再回到数据验证（类似 VisDiff）。
